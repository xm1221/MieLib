# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.0.3.4] - 2026-10-26

Minecraft **1.21.1** line. Maven version is `0.0.3.4+1.21.1`.

### Fixed

- HexCLI is compiled again on 1.21.1 (Fabric + NeoForge). The Gradle source excludes for `cn/xm1221/MieLib/hexcli/**` and `cn/xm1221/MieLib/mixin/hexcli/**` are removed, `Mielib.init()` calls `HexCli.init()` again, and `DedicatedServerConsoleMixin` is re-enabled in `mielib-common.mixins.json` (`server` section), so `> <code>` console rewriting works when HexCLI is active.
- HexCLI's Hex 0.11-only NBT calls are ported to Hex 0.12 codecs/components: parser output now decodes via `IotaType.TYPED_CODEC`, ravenmind uses `HexImageComponents.RAVENMIND` on `CastingImage` components, and image snapshot/reset deep-copy uses `CastingImage.CODEC` instead of removed `serializeToNbt` / `loadFromNbt` / `getUserData` / `IotaType.serialize` / `IotaType.deserialize` / `IotaType.getDisplay` helpers.
- HexCLI's optional hexParse soft-dep is wired for the Fabric/NeoForge dev runtimes (`libs/hexParse-*-1.21.1-1.12.0.pre64.jar`). Loom drops hexParse's jar-in-jar YCLib when remapping, so `libs/yclib-*.jar` (extracted from those jars) is also listed as `modLocalRuntime`. `fabric-loader` is 0.19.5 to satisfy YCLib's declared requirement. Smoke: `> num_1 num_2 add` → stack `[0] 3.00`.
- `HEXCLI.md` now documents 1.21.1 HexCLI support on Fabric + NeoForge (Java 21 dev commands), instead of saying this branch does not compile HexCLI.

## [0.0.3.3] - 2026-10-26

Minecraft **1.21.1** line. Maven version is `0.0.3.3+1.21.1`.

### Fixed

- NeoForge clients no longer crash at startup with `Mixin [mielib-common.mixins.json:GuiSpellcastingMixin] FAILED during APPLY ... could not find any targets matching 'Lat/petrak/hexcasting/client/gui/GuiSpellcasting;method_25394(...)'`. The common refmap is generated by the legacy mixin AP with intermediary (Fabric) names, and it was packed into the NeoForge jar as well, where the runtime is Mojmap. Since 0.0.3.2 actually loads the mixin configs on NeoForge, the bad refmap made the client fail. The NeoForge jar now ships no refmap: `mielib-common.refmap.json` is excluded and the `refmap` key is stripped from `mielib-common.mixins.json` (the mixin sources already use Mojmap names). `remapJar` fails the build if either comes back. The Fabric jar is unchanged and still maps `render` to `method_25394`.

## [0.0.3.2] - 2026-10-25

Minecraft **1.21.1** line. Maven version is `0.0.3.2+1.21.1`.

### Fixed

- NeoForge: MieLib's mixins were never loaded. FML 4 only reads mixin configs from `[[mixins]]` entries in `META-INF/neoforge.mods.toml`, and MieLib declared none, so `CastingVMMixin` (the `@WrapMethod` on `CastingVM.executeInner`) never applied and `CastingVMHook` never ran. Every worker registered through it was silently skipped: MieHex:Revolution's import sets (刻印集) and remote-cast env, and MieHex's mishap catching. `mielib-common.mixins.json` and `mielib-neoforge.mixins.json` are now declared. The GUI/iota-display mixins are fixed the same way.

## [0.0.3.1] - 2026-10-25

Minecraft **1.21.1** line. Maven version is `0.0.3.1+1.21.1` (`modVersion` + Minecraft version).

### Fixed

- NeoForge 1.21.1 clients no longer crash in `RegisterPayloadHandlersEvent` with `Cannot register payload mielib:networking_channel/<uuid> as it is already registered`. Architectury `NetworkChannel.register` registered every message as C2S and, on the client, again as S2C under the same id. NeoForge treats payload ids as unique across directions. Each message is now registered for one direction (`MsgSyncConfigS2C` is server-to-client). A dedicated server registers the S2C payload type, without a client receiver, so it can still sync server config.

### Changed

- `MielibNetworking.CHANNEL` is gone. `NetworkChannel.register` is what double-registered the payload. `sendToPlayer`, `sendToPlayers`, and `sendToServer` are unchanged.

## [0.0.3] - 2026-10-25

Minecraft **1.21.1** line (Fabric + NeoForge). Maven version is `0.0.3+1.21.1` (`modVersion` + Minecraft version, same scheme as 1.20.1). This branch does not replace `main`.

### Changed

- Target Minecraft 1.21.1, Java 21, Architectury 13.0.8, Architectury Loom 1.13-SNAPSHOT, Fabric Loader 0.19.2, Fabric API 0.116.12+1.21.1, NeoForge 21.1.215.
- Loaders are **Fabric and NeoForge**. The Forge module is gone.
- Hex Casting **0.12.0-devel-pre-64** (jars in `libs/`, because BlameJared has no 1.21 Hex artifacts) and PAUCAL **0.7.1-pre-27+1.21.1** (`at.petra-k:paucal`).
- `CastingVM.replaceEnv` still replaces `env` on the existing VM. Hex 0.12's `triggerCreateEvent` takes the current `CastingImage` (the old user-data tag argument is gone).
- `IotaDisplayWorker` now takes the `Iota` instance. Hex 0.12 removed `IotaType.getDisplay` / `getColor` / `KEY_DATA`. The mixin wraps concrete `Iota.displayWithMaxWidth` (what `GuiSpellcasting` calls). `Iota.display()` and `IotaType.color()` are per-subtype overrides and are not wrapped.
- `MieIotas.tryDeserialize(tag, level)` parses `IotaType.TYPED_CODEC` NBT. The old `(type, data, level)` helper is gone with `KEY_TYPE` / `KEY_DATA`.
- `Iota.toSpell()` returns Hex's `TreeList` (`SpellList` was removed).

### Fixed

- `GuiSpellcastingMixin` still leaves `Screen.render` remapped and only marks `RenderLib.drawPatternFromPoints` as `remap = false`, so the pattern-color hook loads on Fabric.

### Removed

- HexCLI is not compiled on this branch. Hex 0.12 dropped the NBT iota and `CastingImage` user-data APIs it calls (`IotaType.deserialize` / `serialize` / `getDisplay`, `CastingImage.getUserData` / `serializeToNbt`). Sources remain under `cn.xm1221.MieLib.hexcli` and are excluded from the compile. See `HEXCLI.md`.

## [Unreleased]

### Added

- `CastingVM.replaceEnv(next: CastingEnvironment)` (`cn.xm1221.MieLib.vm`) replaces `env` on the existing VM and runs `triggerCreateEvent` with the current image user data, so later `executeInner`, `postExecution`, and `postCast` see the new environment. Callers should call it from a Before `CastingVMWorker` and must not cancel just to swap the env.
- HexCLI (now part of MieLib, in `common` / `fabric` / `forge`; no separate mod id or jar): run Hex code in hexParse syntax on a headless dedicated server via `/hexcli run <code>` or raw `> <code>` console lines; persistent stack/ravenmind across commands, `/hexcli stack`, `/hexcli reset`, `/hexcli tick <n>`, `/hexcli wait [quiet] [timeout]`; observes every `CastingEnvironment` on the server (root vs spawned) and logs stack, mishaps and media used.
- HexCLI public env registration API (`cn.xm1221.MieLib.hexcli.api`: `HexCliAPI.registerEnv`, `EnvSpec`, `CasterKind`, `HexCliEnvContext`/`HexCliEnvFactory`), built-in `mielib:packaged` env (cypher/trinket/artifact), `hexcli env list` / `hexcli env use <id|auto>`, profile `envData`, and an unshipped `hexcli_example` addon source set (`:fabric:runHexcliExampleServer`) demonstrating the soft-dependency pattern.
- HexCLI on Forge (`:forge:runHexcliServer`); dev runs `:fabric:runHexcliServer` / `:fabric:runHexcliExampleServer` / `:forge:runHexcliServer`.
- MieLib server config option `enableHexCli` (default `false`) and launch argument `-Dmielib.hexcli=true` to enable HexCLI.
- `HEXCLI.md` at the repo root (moved from `hexcli/README.md`).
- HexCLI standalone terminal client (`hexcli-client` Gradle subproject, plain Java 17, not a mod and not in any mod jar): `:hexcli-client:fatJar` produces `hexcli-client-<version>-all.jar`; connects over loopback to the server's HexCLI remote endpoint (`hexcli/client.json`, random token), JLine REPL with history, multi-line input, tab completion, colored stack rendering, `stack` / `reset` / `env` / `profile` / `media` / `tick` / `wait` / `cmd` / `run` / `cast` / `help` / `quit` commands (bare words matched on the first word, before falling back to hex code), async cast/print events, automatic reconnect, and `--exec <code>` for scripting.
- HexCLI remote server (`cn.xm1221.MieLib.hexcli.remote`): loopback-only newline-delimited JSON protocol with token handshake, structured `run` replies (iotas as JSON with type/text/color/rich segments/children), push events for spawned casts and prints, and `HexCliOps` shared by the console commands and the remote endpoint.
- MieLib server config option `hexCliPort` (default `0` = pick a free port) and launch argument `-Dmielib.hexcli.port=<n>`.
- `HexCliIotas`: entity iotas now render as `<type> "<name>" @ x, y, z #<uuid8>` instead of the Inline placeholder, in console output, ravenmind text and JSON.
- `mielib.utils.extractNestedJar` buildSrc helper (extracts jar-in-jar dependencies such as hexParse's yclib into the dev runtime).

- HexCLI terminal client: `run --step <code>` / `cast --step <code>` steps through the top-level iotas one at a time on the server (`step.begin` / `step.next` / `step.abort`; Enter = next, `c` = continue, `q` = abort, stops on a mishap); `run --file <path>` / `cast --file <path>` casts a UTF-8 `.hexparse` file (combinable with `--step`, path completion), top-level `-f, --file <path>` option, a general `--xxx` option convention for commands, and `docs/examples/hexcli/demo.hexparse`.

### Fixed
- `GuiSpellcastingMixin` no longer marks the whole `@WrapOperation` as `remap = false`. `GuiSpellcasting.render` is `Screen.render` and must be remapped; only the `RenderLib.drawPatternFromPoints` invoke target stays unmapped. Fabric was looking up a method literally named `render` and failing to load.

### Changed
- Before `CastingVMWorker`s can skip the original `executeInner` with `CastingVMCall.setResult` and without `cancel`. A result already set by Before is kept; `cancel` still stops later Before workers and still requires a result.
- HexCLI preloads base Hex `Mishap` first (then common subclasses, esp. `MishapEvalTooMuch`) on `SERVER_STARTED`. HexOP Delay's Gambit recovers from `StackOverflowError` (delay-0 recursion) by `new MishapEvalTooMuch()`; if `Mishap.<clinit>` first runs during that SOE recovery the JVM permanently poisons the base class (`NoClassDefFoundError: Could not initialize class …Mishap`) and every mishap dies. Preload on a healthy stack avoids that. (`Mishap.<clinit>` itself only constructs Companion — no dedicated-server / fake-player init bug.)
- HexCLI crash messages call out mishap-class NCDFE / SOE from recursive delay-0 schedules and say to restart if already poisoned.

- HexCLI terminal client: cast resolution `ESCAPED` is yellow (EVALUATED green; ERRORED / others red).
- **Hex Casting dependency bumped 0.11.3 → 0.11.4** (and its required **Inline 1.20.1-1.0.1 → 1.20.1-1.2.2**). 0.11.4 ships real JVM `default` methods on `ConstMediaAction` (`operate` / `getMediaCost` / `executeWithOpCount`), which fixes `AbstractMethodError` from addons compiled with newer Kotlin `jvm-default` (notably HexOverpowered Delay's Gambit / `OpScheduleCall`). No MieLib mixin needed.
- HexCLI remote: broadcast of async cast/print events no longer NPEs when the write queue had a null stream (delayed HexOP casts can now reach a connected client).
- HexCLI: cast crashes (including `AbstractMethodError`) return a clear error line to the client, not only a server log.


- HexCLI terminal client: each mishap is shown once, prefixed with its step (`! step N: ...`), instead of again as a caster chat `message:`; garbage iotas render as `<garbage>`; list iotas render inline on one line (`[a, [b, c], d]`, per-type element colors, bright depth-colored brackets, `… (+N)` past 500 elements, no manual wrapping); colors too dark for a dark terminal are lightened; truecolor output when the terminal advertises it.
- **HexCLI is off by default** and must be enabled explicitly (`-Dmielib.hexcli=true`, which wins, or `enableHexCli = true` in the MieLib server config); it also needs hexParse installed. Nothing is registered while it is off.
- **HexCLI env ids are now `mielib:staff` / `mielib:circle` / `mielib:packaged` / `mielib:auto`** (bare paths such as `staff` still default to the `mielib` namespace). `HexCliAPI.MOD_ID` is replaced by `HexCliAPI.NAMESPACE` (= `mielib`).
- HexCLI moved from the standalone `hexcli` subproject into MieLib's `common` (loader-agnostic, Architectury events / `@ExpectPlatform` fake player) plus `fabric` / `forge` implementations; `hexcli/` and the `hexcli` mod id are gone, the example addon is the Fabric `example` source set.
- The `> <code>` console shortcut mixin now lives in `cn.xm1221.MieLib.mixin.hexcli.DedicatedServerConsoleMixin` (registered under `server` in `mielib-common.mixins.json`) and only rewrites input while HexCLI is active.
- hexParse is an optional (soft) dependency of MieLib: Fabric `suggests`, Forge non-mandatory dependency, compile-only in `common`.
- **BREAKING**: `IotaDisplayWorker` is now tag-only: constructor is `IotaDisplayWorker(type: IotaType<*>, priority: Int)`, default hook gate is `open fun ifEffect(data: Tag): Boolean = true`, and effect entry is `abstract fun effect(data: Tag, prev: IotaDisplayCall): IotaDisplayCall`.
- Migration: replace `effect(iota: Iota?)` with `effect(data, prev)`, read values from the `KEY_DATA` tag, write needed display info in your iota's `serialize()`, and keep fields of `prev` you don't change.
- `IotaDisplayHook` now executes as `effect(full, initial)`, and workers only run for tags whose `type === worker.type`.
- The `IotaType` mixin is now client-only and wraps static `IotaType.getDisplay` / `getDisplayWithMaxWidth` / `getColor` instead of abstract `display(Tag)`.
- `HookWorkerRegistry` now caches sorted worker order.
- `DrawPatternWorker.ifEffect` / `effect` are now `open` with defaults (`true` / identity) instead of `abstract`.

## [0.0.1] - 2026-10-21

### Added

- Initial version.
- `CastingVMHook` / `CastingVMWorker` / `CastingVMCall` API for extending `CastingVM.executeInner` from addons (MieHex:Revolution etc.).
- `AGENT.md`, the overarching agent guide for working in this repository (including the hook contract).
- Client `DrawPatternHook` / `DrawPatternWorker` registry; a single `GuiSpellcasting` `WrapOperation` on `RenderLib.drawPatternFromPoints` lets addons rewrite `drawLast`/`tail`/`head`/`flowIrregular` (workers run in ascending priority).
- Client `IotaDisplayHook` / `IotaDisplayWorker` registry for overriding iota display text.
- `PriorityWorker` interface and `HookWorkerRegistry<W>` shared registry backing `CastingVMHook`, `DrawPatternHook`, and `IotaDisplayHook` (`ordered()` + `fold`).

### Fixed

- `CastingVM.executeInner`'s original method is now called **exactly once** on the success path and **zero times** when a Before worker cancels; previously it could be called two or three times per cast.
- Before-stage cancellation no longer silently falls back to `original.call(...)`. A Before `cancel` without a result now throws instead of effectively un-cancelling the hook.
- After workers now run even when a Before worker cancelled the original call, so cleanup/logging hooks are not skipped. The After phase starts with `cancelled` cleared (the result is kept), so a Before-stage cancel no longer truncates the After chain after the first worker; only an After-stage `cancel` stops later After workers.
- After-stage `cancel` no longer re-invokes the original method; it adopts the current `result` and stops later After workers.
- A missing final `CastResult` now fails loudly with `IllegalStateException` rather than returning `null`.

### Changed

- Hook execution order is now **ascending `priority`**, with ties broken by the id string, instead of registration order.
- `CastingVMCall.cancel()` is now `cancel(result: CastResult)`; `result` has a private setter and a new `setResult(result)` is available for After workers that only want to rewrite the return value.
- `CastingVMWorker` has a single `execute(...)` entry point; the separate `beforeExecute` / `afterExecute` abstract methods were removed in favour of the `isAfter` constructor parameter.
- Workers now receive the `CastingVM` instance (`vm`), allowing hooks to read/modify the VM image and environment.
- `CastingVMHook` KDoc updated to describe the actual pipeline.
- Duplicate `CastingVMHook.register` ids **overwrite** the previous worker (with a warn log) instead of throwing, so addons can replace a hook flexibly.
- `CastingVMWorker` / `DrawPatternWorker` / `IotaDisplayWorker` implement `PriorityWorker`; constructors unchanged for source compatibility.
- `DrawPatternHook` / `IotaDisplayHook` now use the same `ConcurrentHashMap` + overwrite-warn + id-tiebreak behaviour as `CastingVMHook` (was silent overwrite / unordered ties).
- `CastingVMHook.execute` semantics unchanged; only ordering lookup moved to `HookWorkerRegistry.ordered()`.
